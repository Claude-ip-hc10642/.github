<p>批量续费之前，最该做的一件事是拿几条样本把"出身"查清楚。所谓出身，不是供应商说的自营或直签，而是能自己验证的四项：ASN 归属、类型标签、注册地一致性、历史滥用记录。这四项花半小时能查完，却能避免几十个号白注册。这篇按决策清单组织：先讲出身怎么拆成可查的证据，再说样本取几条够用，然后给一张逐项打钩的续费前清单，最后是判定规则和批量续费前的三道闸。</p>

<h2>一、把"出身"拆成四件可查的事</h2>
<p>"干净"这个词太笼统，落到操作上必须能对应具体查询。四项证据各自独立，可以分别验证，也可以互相印证。四项全过，才有资格谈批量。</p>
<h3>第一件：ASN 与运营商名称</h3>
<p>查地址所属自治系统，看名称是宽带运营商还是云厂商、数据中心。住宅运营商的 ASN 名称通常带有 telecom、broadband、cable、fiber 这类词，IDC 则常见 cloud、hosting、server、data。这一步用 whois 就能完成，几秒钟出结果。</p>
<h3>第二件：类型标签与注册地</h3>
<p>用两到三个 IP 情报库交叉查分类标签，看是否一致标为住宅；同时核对注册国家与城市，是否与你账号资料里填的地区自洽。标签打架时按更严格的结果算，注册地明显不符的直接排除。</p>
<h3>第三件：近九十天的滥用记录</h3>
<p>查公开黑名单与滥用投诉库。重点不是有没有历史记录，而是最近九十天有没有新增。一条三年前被投诉过、之后一直安静的地址，通常问题不大；一条上个月刚被投诉过的，即使现在没人用，也可能已经被降权。</p>
<h3>第四件：同段的邻居情况</h3>
<p>单条地址干净不代表整段干净。看同一个 C 段里其他地址的标签与投诉情况，整段都被标记的，单条再好也不建议用。这一项查起来稍麻烦，但可以用情报站的网段查询功能快速扫一遍。</p>

<h2>二、试用样本取几条才够</h2>
<p>只试一条，运气成分太大；试太多，成本又上去了。合理区间是三到五条，覆盖不同的地址段和不同的开通批次，这样能同时验证"单条质量"和"批次一致性"。</p>
<h3>为什么至少三条</h3>
<p>一条地址表现好，可能只是碰巧分到一条还没被用过的。三条里有两条表现一致，才能初步判断这是产品水平而不是运气。三条都不行，基本可以直接放弃这家。</p>
<h3>为什么要跨批次</h3>
<p>供应商的地址池可能分批进货，不同批次的质量差别很大。只试同一批，等于只验证了这一批。条件允许的话，隔几天再开一条，看新批次的属性是否一致。</p>

<h2>四、什么情况续、什么情况退</h2>
<p>判定规则要提前定好，别等数据出来了再临时商量，那时候容易被"已经投入这么多"的心理带偏。下面三条规则可以照着用。</p>
<h3>规则一：四项证据有两项不过，直接退</h3>
<p>四项里两项不过，说明这批地址的基本面有问题，不是个别瑕疵。这种情况继续试用的意义不大，直接换一家比争取换址更省时间。特别注意不要因为"价格便宜"而放宽这条。</p>
<h3>规则二：只有稳定性不过，先延长观察</h3>
<p>属性全对但偶有掉线，可能是本地网络或时段因素。这种情况不建议立刻退，先把观察期延长到七到十天，把掉线时间点和本地网络状况对照一遍。确认是上游问题再谈退或换。</p>
<h3>规则三：全部通过但价格偏高，可以谈</h3>
<p>四项全过、稳定性也好的供应商不多，遇到这种可以先谈价而不是直接换。谈的筹码就是你的用量和续费周期，量稳定的话，谈到九折到八五折不罕见。</p>

<h2>五、批量续费前的三道闸</h2>
<p>单条通过不等于可以批量。批量之前还要过三道闸，每道闸对应一类风险：规格、账期、退出。</p>
<h3>第一道：规格闸</h3>
<p>确认要续的条数、每条对应的账号、续费周期。条数按同时活跃的号数定，别按总号数定。周期上，新供应商第一次批量续，建议只续一个月，跑满一个完整周期再谈季付或年付。</p>
<h3>第二道：账期闸</h3>
<p>确认扣费时间、扣费方式、发票或凭证怎么开。季付年付的折扣往往伴随锁定期，一旦中途要换，剩余费用能否退、怎么退，这条要提前问清楚并留下书面记录。</p>
<h3>第三道：退出闸</h3>
<p>想清楚如果这批地址三个月后质量下滑，你怎么退。是逐条停、整批停、还是转成备用线？退出路径清晰的方案，即使贵一点也值得；退出困难的方案，便宜也是陷阱。</p>

<h2>常见问答</h2>
<h3>四条证据里哪条最重要？</h3>
<p>答：ASN 归属。它决定了地址的根本属性，其他三项都是在属性正确的前提下才有意义。ASN 指向机房，剩下的标签、注册地、滥用记录都不用看了，直接排除。</p>
<h3>供应商说可以保证纯净，还需要自己查吗？</h3>
<p>答：需要。保证是承诺，查询是事实，两者不冲突但也不能互相替代。自己查一遍，一方面是验证，另一方面是留证据——真出问题时，你手上的查询记录比口头承诺有用得多。</p>
<h3>试用到第几天可以下结论？</h3>
<p>答：属性类证据当天就能出结论，稳定性类至少要四十八小时。建议的做法是当天查完四项，然后挂两天看稳定性，第三天再决定。急着当天决定，稳定性这一项就是空的。</p>
<h3>批量续费后发现个别地址不行，怎么办？</h3>
<p>答：先按单条处理，别整批退。把不行的地址挑出来要求换，其余的继续用。同时把问题记录进台账，如果同一批次里不行超过三成，说明这批货整体有问题，那时候再考虑整批处理。</p>
